# 장비 중심 사이트 설계안 (PECVD·ALD)

- 승인: 2026-11-21
- 작업 브랜치: `equipment-redesign` (`redesign`에서 만듦 — GSAP·sim-core·PVD 단면도가 있는 최신 브랜치)
- 이 문서는 "무엇을 어떤 순서로 만들지"를 적은 설계서다. 코드를 쓰기 전에 여기를 먼저 본다.

## 승인된 결정 사항
1. 브랜치: `redesign` → `equipment-redesign`
2. 출처 규칙: 실제로 열어 보고 확인한 자료만 URL·특허번호·확인 날짜와 함께 적고, 확인하지 않은 것은 종류만 적는다.
3. 그리기 방식: **2.5D 아이소메트릭 SVG + GSAP**로 시제품. 단, 장비 데이터는 그리는 코드와 **완전히 분리**해서 나중에 Three.js 3D로 바꿔도 데이터는 그대로 쓴다. (아래 "데이터–그리기 분리")
4. 스킬: `gsap-performance`(GreenSock 공식) 설치. Three.js 스킬·isokit은 설치하지 않음.
5. 외형 품질: 면마다 명암, 얇은 외곽선, 패널 이음선·볼트·통풍구 디테일로 실제 장비 외장 패널 느낌. (아래 "외형 품질 기준")
6. (1-A, 2026-11-21) 펌프는 공정 챔버마다 1대씩 서브팹에 두고 챔버별 독립 배기로 연결(`copyOf`로 4대). 서체는 IBM Plex Mono 하나만 추가. 트랜스퍼 챔버 약어는 **TM(Transfer Module)**으로 통일.
7. (1-A) 포인트 색(공정 색)은 장비 그림에서 **선택(강조)된 부품의 외곽선·지시선에만** 쓴다.

## 1. 사이트 전체 구조 (메뉴)
```
홈          장비 2대(PECVD·ALD) 큰 카드 + 검색
장비 ★      PECVD 장비 · ALD 장비 · (나중에) PVD / Epi / ECD
공정 원리    기초(진공·플라즈마·박막 성장) + 원리 보기(PVD 단면도 등 모션)
부품 사전    모든 장비의 부품 목록 (데이터에서 자동 생성)
면접 대비    모든 부품의 면접 질문 모음 (데이터에서 자동 생성)
장비사       공개된 제품군만, 출처·확인 날짜와 함께 (확인한 것만)
실습 기록    그대로
```

## 2. 장비 페이지 스크롤 흐름
화면 하나를 고정(pin)하고, 스크롤 양에 따라 **하나의 타임라인**이 앞뒤로 재생된다(scrub). 장면을 갈아끼우지 않으므로 끊김이 없다.

| 구간 | 스크롤 | 화면 |
|---|---|---|
| ① 외관 | 0–10% | 장비 전체가 크게. "대표적인 300mm PECVD 장비 구성" + "스크롤해서 분해" 안내 |
| ② 모듈 분해 | 10–40% | EFEM·로드락·트랜스퍼 챔버·공정 챔버·가스 박스·RF 전원/매칭·펌프/배기가 벌어지고 이름표가 차례로 등장 |
| ③ 웨이퍼 경로 | 40–50% | FOUP → EFEM → 로드락 → 트랜스퍼 → 공정 챔버 경로를 점선으로 |
| ④ 챔버 집중 | 50–60% | 다른 모듈은 흐려지고 공정 챔버로 확대 |
| ⑤ 챔버 2차 분해 | 60–90% | 뚜껑·샤워헤드 위로, 히터/서셉터·리프트 핀 아래로, 라이너 바깥으로. 배기 포트·RPS 이름표 |
| ⑥ 마무리 | 90–100% | 고정이 풀리고 아래 본문(기존 7섹션)으로 이어짐 |

- 이름표 클릭 → **부품 상세 패널** (컴퓨터: 오른쪽 패널 / 휴대폰: 아래에서 올라오는 시트).
  내용: 역할 · 동작 원리 · 관련 공정변수 · 자주 생기는 문제와 PM 점검 · 면접 질문 · 출처 · (있으면) "원리 보기"
- 주소 `#part=showerhead`로 특정 부품을 바로 연다. 이름표는 `<button>`(키보드 가능).
- **대체 화면**: 움직임 줄이기 / 데이터 절약 / 저사양 기기 → 분해가 끝난 그림 1장 + 이름표 + 부품 목록. 판정은 `sim-core.js`의 기존 로직을 공용으로 꺼내 쓴다.

## 3. 데이터–그리기 분리 (3D 전환 대비)
**원칙: 데이터 파일에는 "무엇이 어디에 어떤 모양으로 있나"만 적고, "어떻게 그리나"는 적지 않는다.**

- 좌표계: 실제 3D 공간 기준. `x` = 오른쪽, `y` = 안쪽(깊이), `z` = 위. 단위는 추상 단위 `u`
  (그림 비율용일 뿐 실제 치수·사양이 아니다 — 수치·사양 금지 규칙과 충돌하지 않음).
- 데이터에 **넣지 않는 것**: 화면 픽셀 좌표, SVG 경로, 색 값, 아이소메트릭 각도, 카메라.
- 데이터에 **넣는 것**: 3D 기본 도형 + 크기 + 위치 + 분해 방향 + 재질 "이름" + 디테일 "종류".
- 그리는 쪽(렌더러)이 이것을 해석한다:
  - 지금: `js/explode/render-iso.js` → 아이소메트릭 SVG
  - 나중: `js/explode/render-3d.js` → Three.js (같은 데이터를 읽음)
  - 스크롤 연출(`stage.js`)은 렌더러에게 "분해 정도 0~1"만 넘긴다 → 렌더러를 바꿔도 연출 코드는 그대로.

```js
// data/pecvd.js  (fetch 금지 → JSON 모양의 .js 파일)
window.EQUIPMENT = window.EQUIPMENT || {};
window.EQUIPMENT.pecvd = {
  id: "pecvd", title: "PECVD 장비", process: "cvd",
  platform: "common-300",            // EFEM·로드락·트랜스퍼는 data/platform.js에서 가져옴
  parts: [{
    id: "showerhead", name: "샤워헤드", en: "Showerhead",
    parent: "pm", level: 2,           // 1 = 모듈, 2 = 챔버 내부 부품
    // ── 형태 (렌더러가 해석) ──
    shape: "disk",                    // box | cylinder | disk | plate-holes | pipe ...
    size: [/* 폭, 깊이, 높이 (u) */],
    pos:  [/* x, y, z (u), 부모 기준 */],
    explode: [0, 0, 1],               // 분해 방향(단위 벡터) × 거리
    explodeStep: 2,                   // 1 = 모듈 분해 때, 2 = 챔버 2차 분해 때
    material: "metal",                // panel | metal | ceramic | quartz | dark ... (색은 렌더러가 정함)
    details: [{ type: "holes", face: "bottom" }], // seam | bolts | vent | holes | window | label-plate ...
    label: { anchor: "top" },
    // ── 학습 내용 ──
    role: "", principle: "",
    params:    [{ name: "", up: "", down: "", tradeoff: "" }],
    issues:    [{ problem: "", checks: [] }],
    pm:        [],
    interview: [{ q: "", a: "", cs: false }],  // cs = CS 엔지니어 관점 질문
    sim: null,                        // "pvd" 등 → '원리 보기' 버튼
    verify: [],                       // [검증 필요] 항목
    sources: [{ kind: "일반 교과서 내용" }] // 확인한 자료면 { kind, title, url 또는 patent, checked: "YYYY-MM-DD" }
  }]
};
```
- 이미 있는 도형 종류로 그릴 수 있는 부품은 **데이터만 추가**하면 된다. 완전히 새 도형이 필요할 때만 렌더러에 도형 함수를 하나 추가한다.
- ALD: `data/ald.js`도 `platform: "common-300"`을 써서 EFEM·로드락·트랜스퍼를 재사용하고, 고속 ALD 밸브·전구체 앰플/공급 장치·가열 배관·퍼지 라인 등 고유 부품만 추가. 열 ALD/PEALD의 RF 유무는 [검증 필요].

## 4. 외형 품질 기준 (싸구려 느낌 방지)
렌더러가 지키는 규칙 (데이터는 재질·디테일 "이름"만 줌):
- **면마다 명암**: 빛은 왼쪽 위에서 온다고 가정. 윗면 가장 밝게, 왼쪽 옆면 중간, 오른쪽 옆면 가장 어둡게.
  재질마다 기본 색 1개 → 세 면 밝기는 계산으로 만든다 (색은 `:root` 변수에서 가져옴).
- **얇은 외곽선**: 외곽선은 가늘고 면보다 약간 어두운 색. 두꺼운 검은 선은 쓰지 않는다. 바깥 윤곽만 조금 진하게.
- **패널 이음선(seam)**: 큰 면을 몇 장의 패널로 나누는 가는 홈 선 (어두운 선 + 바로 옆에 밝은 선 = 홈처럼 보이게).
- **볼트(bolts)**: 패널 모서리나 플랜지 둘레에 작은 점. 원근에 맞게 타원.
- **통풍구(vent)**: 얇은 평행 슬롯 여러 줄 (전원·펌프 쪽 패널).
- 그 밖에: 관찰창(window), 표시판(label-plate, 글자 없이 빈 판), 배관 플랜지, 은은한 모서리 하이라이트.
- **하지 않는 것**: 실제 회사 제품 외형 따라 그리기, 로고, 과한 그라디언트·그림자·네온, 블러 필터(휴대폰에서 느림).
- 디테일은 분해 중에도 조각과 함께 움직이도록 같은 SVG 그룹 안에 둔다.

## 5. PVD 단면도(js/sim/) 재사용
- `sim-core.js`에 `ProcessSim.mount(요소)`를 추가 → 패널이 열릴 때 그 안의 캔버스를 시작하고 닫을 때 멈춘다.
- 부품 데이터 `sim: "pvd"` → 패널에 "공정 챔버 원리 보기" 버튼 → 단면도 팝업.
- PECVD용 단면도(샤워헤드 → 플라즈마 → 막 성장)는 같은 엔진으로 나중에 새 장면을 만든다.

js/explode/stage.js               무대 + 스크롤 타임라인 + 대체 화면 (렌더러와 무관)
